\section{Test Plan}

The plan follows the outline of IEEE Std 829 \cite{pressman2014se}.

\begin{table}[H]
\centering
\footnotesize
\begin{tabularx}{\textwidth}{>{\raggedright\arraybackslash}p{0.19\textwidth} L}
\toprule
\textbf{Item} & \textbf{Plan} \\
\midrule
Objective & Show that every functional requirement (Table~\ref{tab:fr}) works, that no user can reach another's data, and that search quality does not regress. \\
Version under test & \texttt{master} branch on 26~November 2026; extension 2.4.2. \\
Scope & Backend API and pipelines, web app, extension logic, search quality. Not tested: the third-party services themselves (mocked), browsers other than Chrome, load beyond one server. \\
Levels and types & \textbf{Unit} tests for pure logic; \textbf{integration} tests of the API through FastAPI's test client with an in-memory Solr that honours the user filter; \textbf{system} evaluation against a real Solr core (Section~\ref{sec:evaluation}); \textbf{manual} checks in the browser. Functional, security, privacy, regression and performance tests. \\
Environment and tools & pytest (Python 3.11 in CI, 3.12 locally); Vitest and \texttt{svelte-check} on Node 20; Solr 9.7 in Docker; Chrome. \\
Test data & Fixture pages and users inside the tests; the SciFact corpus (1{,}000 abstracts, 100 claims) for the evaluation. \\
Entry criteria & The change builds; required Solr fields exist. \\
Acceptance (exit) criteria & All automated tests pass; type check clean; SciFact Hit@1 and MRR@10 not below the previous run beyond its confidence interval; the save, search, delete and sign-in flows work in the browser. \\
Regression rule & Every bug fixed gets a test that fails without the fix. \\
Schedule & Unit and integration tests on every push (CI); the evaluation before each retrieval change; manual checks after each deployment. \\
Risks & Mocks can hide real-service behaviour (mitigated by live checks); 100 claims give wide intervals (reported with every result). \\

\paragraph{Totals.} Of the 20 test cases, 20 were executed and 20 passed;
none are planned-only or blocked. The full automated suites, which include
these, were run on the same day: \textbf{566 tests (430 backend with pytest,
136 frontend and extension with Vitest), 566 passed, 0 failed, 0 skipped},
and \texttt{svelte-check} reported no errors. The largest suites cover the
extension's capture rules (76), content cleaning and chunking (50), query
understanding (46), ingestion (45) and accounts and sign-in (45). The
retrieval evaluation is reported in Section~\ref{sec:evaluation}.
