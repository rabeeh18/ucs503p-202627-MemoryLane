# 0001. One Solr core for keyword and vector search

**Status:** Accepted · **Date:** August 2026

## Context

MemoryLane has to find a page whether the user remembers its exact words (a product name, an error code) or only its meaning ("that article about sleep and memory"). That needs two kinds of search over the same pages: keyword search (BM25) and vector search (KNN over embeddings).

The first prototype stored embeddings in **ChromaDB**. It did vector search well, but had no BM25, so exact names and rare words were often missed. MemoryLane would also become multi-user, so every search had to be limited to one person's pages *before* ranking, not filtered afterwards.

## Decision

Store everything in one **Apache Solr 9** core. Each chunk is one document holding its text (`text_en`: stemming and stopwords, for BM25) and its embedding (`DenseVectorField`, HNSW, cosine, for KNN). Every query carries a `user_id` filter, which KNN applies as a **pre-filter**.

## Alternatives

| Option | Why not |
| --- | --- |
| Keep ChromaDB and add a separate BM25 library | Two stores to keep in sync on every save and delete, and user filtering in two places |
| Elasticsearch or OpenSearch | Same capabilities as Solr; no clear advantage for this project, and heavier to run on a small server |
| PostgreSQL with full-text search and pgvector | One database, but its full-text ranking isn't BM25, and tuning it would take longer |
| A hosted vector database | Vector search only, a monthly cost, and personal data leaving the server |

## Consequences

- **Easier:** one write path, one delete path and one place to enforce isolation (`backend/solr_client.py`). Hybrid search is two requests to the same core.
- **Harder:** Solr runs on the JVM, so it needs memory (1 GB heap on the live server). The schema has to be installed by script, because automatic field creation is off so mistakes fail loudly.
- The chunk embedding isn't stored (to save space), so Solr atomic updates can't be used: they'd silently drop it. Scripts rewrite whole pages instead.
